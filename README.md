# 羽球 HUD 編輯器

把一段固定機位的雙打影片，變成像遊戲畫面的 HUD 影片：
- 回合時間、擊球數、球速（估算）、比分；
- 每位球員頭上的名字與體力條、腳下的光圈；
- 我隊衝刺時的 MOVE / ARRIVED 目標標記；
- 擊球瞬間的 LOCK ON 球速；
- 左下角四位球員的體力與移動量，右下角的球場地圖；
- 得分時的「我隊 得分」橫幅與落點特效。

## 開始

```bash
cd ~/Claude/badminton-hud
uv run hud web
```

打開 http://127.0.0.1:7860 ，然後：

1. **上傳影片**：拖進網頁即可。
2. **校正球場**：會自動偵測，也可以自己調整。
   - 黃線應該對齊地上的白線，對不準就拖四個角。
   - 角落在畫面外也沒關係，拖到灰色區域即可。
   - 預設顯示「背景」：多幀合成，球員會消失，白線最清楚。
   - 點一個角後可以用方向鍵微調；「貼齊白線」會自動把線吸到白線上。
3. **球員名字**：近端（靠鏡頭）是我隊，左邊是 1 號。
4. **開始分析**。
5. **修正比分**：得分方是自動判斷的，猜錯就在表格裡改，再按「套用修正並重新輸出」。這只重跑最後兩步，幾秒就好。

命令列（自動偵測球場，跑完整流程）：

```bash
uv run hud run 影片.mp4
```

用 `--from rallies` 可以只從某一步重跑。

想讓同 Wi-Fi 的手機也能開：`uv run hud web --lan --password 自己設的密碼`。

## 拍攝建議

**整段影片必須是同一個固定機位。** 鏡頭移動、縮放，或是螢幕錄影時放大播放畫面，都會讓校正失效。

| | 建議 |
|---|---|
| 機位 | 正後方或後方 45°；放椅子上也可以，越高越好 |
| 鏡頭 | 1x 主鏡頭（0.5x 超廣角會把直線拍彎） |
| 固定 | 拍攝中不要動手機：校正是整段共用的 |
| 畫質 | 至少 720p，光線充足；60 fps 優於 30 fps |

## 速度（8 GB Apple Silicon，實測）

| 影片 | 總時間 | CPU 時間 |
|---|---|---|
| 37 秒 1080p 60 fps（斜角） | 約 1 分 45 秒 | 44 秒 |
| 60 秒 2940×1912（螢幕錄影） | 約 2 分 30 秒 | 82 秒 |

舊版：37 秒的片段要 10 分鐘以上；60 秒的 3K 片段，光解碼就吃掉 400 多秒 CPU。

| 步驟 | 做法 |
|---|---|
| 球場偵測（約 6 秒） | 多幀合成背景 → 找白線 → 所有線的組合一次批次評分 → 檢查相機位置是否合理 → 試各種線的對應（單打線／雙打線）→ 貼齊 |
| 球員 | YOLO11n-pose（nano），每秒 10 次，中間插值；遠端半場再裁切放大偵測一次 |
| 羽球 | TrackNetV3，每一幀、半精度 |
| HUD 影片 | 單一程序、硬體 H.264 編碼；輸出長邊最多 1920 px、最多 30 fps |

所有解碼和縮小都交給 Mac 的硬體（VideoToolbox），所以 CPU 幾乎不受影片解析度影響。

試過但不採用：
- **純移動偵測找球（不用 TrackNet）**：快很多，但 10 個擊球只找到 2 個。
- **TrackNet 隔一幀跑**：3 個回合漏掉 2 個。

## 準確度

斜角測試片段（3 個回合、10 個人工標記的擊球），全自動、包含自動校正：
- 回合：3 個都找到，但多了 2 個誤判，是撿球、遞球被當成回合。
- 擊球方（近端／遠端）：7/7 正確。
- 比分：
  - 球落地且看得到時，依落點判斷界內或界外。
  - 看不到落點時，猜最後擊球的一方得分。
  - 網頁上可以逐回合修正，誤判的回合也可以設成「不算」。

看台很暗、人很多的場館（例如 MCC 螢幕錄影）：羽球常常消失在觀眾背景裡，回合會被切短或漏掉。這是羽球模型（TrackNet）的極限。拍攝時盡量讓背景單純、光線充足。

## 測量值 vs 估算值

| 項目 | 性質 | 說明 |
|---|---|---|
| 回合時間、擊球數 | 測量值 | 漏掉的擊球會少算 |
| 球員位置、球場地圖 | 測量值 | 單鏡頭推算，遠端誤差較大（約 10–30 cm） |
| 球速 | **估算值** | 只有一個鏡頭，球的深度要用推的；誤差約 ±20–30%，超過 450 km/h 的會丟掉 |
| 球種（殺球／高遠／吊球／網前／平抽） | 規則判斷 | 依球速、擊球高度與落點 |
| 體力 | **遊戲化指標** | 回合中每跑 1 m 扣 1.5、衝刺每秒扣 4，回合間每秒回 3；不是生理量測。公式在 `config.toml` |
| MOVE | 測量值換算 | 最近 3 秒的移動距離 ÷ 8 m |
| 落點評分（PERFECT／GREAT…） | 規則評分 | 依球種的理想落點計算，不是裁判判決 |

## 檔案

```
hud/
  court.py      球場模型、自動偵測（角落可在畫面外）、貼齊白線
  camera.py     從球場單應矩陣還原相機（讓空中的球有 3D 位置）
  detect.py     YOLO11n-pose + 遠端裁切偵測
  players.py    四人身份追蹤（每半場 2 人，匈牙利配對）
  reid.py       跨回合換 ID 修正
  shuttle.py    TrackNetV3 羽球追蹤
  hits.py       擊球、擊球者、球速、球種
  rallies.py    回合切分、落點評分
  score.py      計分（21 分制、deuce、30 分封頂）
  render.py     HUD 影片
  server.py     網頁編輯器（只用 Python 標準函式庫）
  static/index.html
config.toml     可調參數（顏色、回合、計分、體力）
out/<影片>/      每部影片一個資料夾：calib.json、*.parquet、hud.mp4（重跑會覆蓋，不會重複）
```

## 費用與授權

- 全部在這台 Mac 本機執行：沒有付費 API、沒有雲端伺服器、沒有外部資料庫。
- 第三方程式碼與模型：
  - **YOLO11（Ultralytics）**：AGPL-3.0。自己用沒問題；做成公開服務或商業用途，需要開源或另購授權。
  - **TrackNetV3**：MIT（`hud/tracknet/`，只複製了模型定義）。
- 舊版專案移到了 `~/Claude/_archive/badminton-analyzer-old`（沒有刪除）。

## 在其他電腦或雲端繼續開發

```bash
git clone https://github.com/deYewwww/badminton-buddy && cd badminton-buddy
uv sync
for f in tests/test_*.py; do uv run python $f; done
```

- 需要 ffmpeg（Mac：`brew install ffmpeg`；Linux：`apt-get install ffmpeg`）。
- 沒有 Apple 晶片時，會自動改用軟體解碼和 CPU，速度較慢。
- 影片和分析結果不在 git 裡。

## 測試
