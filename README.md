# 羽球 HUD 編輯器

把一段固定機位的雙打影片，變成像遊戲畫面的 HUD 影片：
- 回合時間、擊球數、球速（估算）、比分；
- 每位球員頭上的名字與體力條、腳下的光圈；
- 我隊衝刺時的 MOVE / ARRIVED 目標標記；
- 擊球瞬間的 LOCK ON 球速；
- 左下角四位球員的體力與移動量，右下角的球場地圖；
- 得分時的「我隊 得分」橫幅與落點特效。

## 開始

```bash
cd ~/Claude/badminton-hud
uv run hud web
```

打開 http://127.0.0.1:7860 ，然後：

1. **上傳影片**：拖進網頁即可。
2. **校正球場**：會自動偵測，也可以自己調整。
   - 黃線應該對齊地上的白線，對不準就拖四個角。
   - 1–4 號點預設是球場四個角。角落在畫面外也沒關係：畫面會自動留出灰色區域，把角拖過去，讓黃線延伸出去對齊白線。
   - 也可以按「控制點」改用畫面內看得到的四個白線交叉點（角離畫面太遠或在鏡頭後面時會自動改用）。
   - 預設顯示「背景」：多幀合成，球員會消失，白線最清楚。
   - 點一個角後可以用方向鍵微調；「貼齊白線」會自動把線吸到白線上。
   - **場地（建議）**：第一次去一個場地時，先拍 5–10 秒空場（同一次錄影的開頭也可以：把「畫面」拉到那段再按「自動偵測」）。空場沒有人擋線，校正最準；可以請朋友在遠端兩個角各放一個球筒。校正好後輸入名稱按「存成場地」。之後在同一個位置拍的比賽，選這個場地按「套用場地」：程式會自動對齊（手機稍微被碰到也沒關係），差太多會提示你重新校正。
3. **球員**：輸入名字；再選一位球員，在畫面上點他兩腳中間（近端是我隊、遠端是對手）。建議在第一個回合前把 4 個人各點一次；之後哪一段認錯人，就把畫面拉到那個時間再點一次，從那裡開始修正。
4. **開始分析**。
5. **修正比分**：得分方是自動判斷的，猜錯就在表格裡改，再按「套用修正並重新輸出」。這只重跑最後兩步，幾秒就好。

命令列（自動偵測球場，跑完整流程）：

```bash
uv run hud run 影片.mp4
```

用 `--from rallies` 可以只從某一步重跑。

鏡頭有轉動（雲台追蹤）或剪接過的影片：**不用另外處理**。打開影片時會自動檢查鏡頭有沒有動；有動的話，請在一個清楚的畫面（不是背景圖）上校正，分析時會先把每一幀穩定到這個畫面（`out/<影片>/stab.mp4`），所有球員、羽球、比分都在固定視角下計算，HUD 再逐幀畫回原始影片。也可以手動先穩定化（`--ref` 是用來校正的那一秒）：

```bash
uv run hud stabilize 影片.mp4 --ref 63 --out data/穩定.mp4
```

驗證準確度：照 `hud/evaluate.py` 開頭的格式寫一個 truth.json（回合起訖、得分方、擊球），然後：

```bash
uv run hud eval out/<影片> truth.json
```

用存好的場地（不做自動偵測）：

```bash
uv run hud venue-save "DT 第5場 右後方" --from out/空場影片
uv run hud run 比賽.mp4 --venue "DT 第5場 右後方"
```

每次分析完，各步驟花的秒數會寫在 `out/<影片>/timing.json`。

結果不對（沒有對手、沒有拍數、沒有比分）時，先跑健康檢查，它會指出是哪一步壞掉：

```bash
uv run hud check out/<影片>
```

它會寫出 `check.json` 和 `check.png`（黃線 = 校正的球場，彩色點 = 偵測到的球員腳位）。分析完成時也會自動檢查，有問題會顯示在「開始分析」旁邊。

Mac 上第一次用之前，建議先跑一次（約 1 分鐘）：把 TrackNet 轉成 CoreML，用 Neural Engine 跑羽球追蹤。程式會在每支影片開頭自動和原版比對，不一致就自動改回原版，結果不會變。

```bash
uv run --with numpy==2.3.5 hud export-coreml
```

（`--with numpy==2.3.5` 是給 YOLO 的匯出用的：Ultralytics 的 CoreML 匯出在 numpy 2.4 會失敗。只寫 `uv run hud export-coreml` 也可以，TrackNet 照樣會轉好，YOLO 會跳過。）

想讓同 Wi-Fi 的手機也能開：`uv run hud web --lan --password 自己設的密碼`。

## 拍攝建議

**固定機位最準。** 雲台轉動、剪接會自動穩定化（只要手機是原地轉動），但縮放、或是螢幕錄影時放大播放畫面，仍會讓校正失效。

| | 建議 |
|---|---|
| 機位 | 正後方或後方 45°，**越高越好（1.5–2 m 以上）**。手機離地 0.4 m 時，遠端底線附近 1 個像素 ≈ 1.2 m 深度，遠端球員的位置會亂跳；架到 2.5 m 約 0.2 m |
| 追蹤 | 最好關掉雲台自動追蹤、iPhone「人物居中」。轉動的影片會自動穩定化，但轉動時的模糊幀和視差會損失一點準確度 |
| 方向 | 橫拍。直拍也能跑（羽球追蹤會自動裁出 16:9 區域），但天花板佔掉一半畫面 |
| 鏡頭 | 1x 主鏡頭（0.5x 超廣角會把直線拍彎） |
| 固定 | 拍攝中盡量不要移動手機位置（原地轉動可以，走動不行） |
| 畫質 | 至少 720p，光線充足；60 fps 優於 30 fps |

## 速度（8 GB Apple Silicon，實測）

| 影片 | 總時間 | CPU 時間 |
|---|---|---|
| 37 秒 1080p 60 fps（斜角） | 約 1 分 45 秒 | 44 秒 |
| 60 秒 2940×1912（螢幕錄影） | 約 2 分 30 秒 | 82 秒 |

舊版：37 秒的片段要 10 分鐘以上；60 秒的 3K 片段，光解碼就吃掉 400 多秒 CPU。

| 步驟 | 做法 |
|---|---|
| 球場偵測（約 6 秒） | 多幀合成背景 → 找白線 → 所有線的組合一次批次評分 → 檢查相機位置是否合理 → 試各種線的對應（單打線／雙打線）→ 貼齊 |
| 球員 | YOLO11n-pose（nano），每秒 10 次，中間插值；只偵測球員活動的區域（直拍、穩定化畫面中球場只佔一小塊，整張縮小時 nano 會漏人）；遠端半場再裁切放大偵測一次 |
| 羽球 | TrackNetV3（有 CoreML 版就用 Neural Engine），每一幀、半精度；死球時間（至少 3 位球員都站著或慢走）跳過，前後各留 2 秒，球還在空中就繼續追。遠端球場在畫面裡很小時（直拍、穩定化、低機位）再對遠端放大跑一次，補主畫面漏掉的幀（ACE：對打中找到率 52% → 58%，TrackNet 時間約 +60%，`far_pass = false` 可關）。設定在 `config.toml` 的 `[shuttle]` |
| HUD 影片 | 單一程序、硬體 H.264 編碼；輸出長邊最多 1920 px、最多 30 fps |

所有解碼和縮小都交給 Mac 的硬體（VideoToolbox），所以 CPU 幾乎不受影片解析度影響。

試過但不採用：
- **純移動偵測找球（不用 TrackNet）**：快很多，但 10 個擊球只找到 2 個。
- **TrackNet 隔一幀跑**：3 個回合漏掉 2 個。

## 羽球偵測器（選用，在 Mac 上訓練一次）

TrackNet 是靠「球在動」找球：很小、很糊的球它找得到，但有些清楚可見的球（在看板前、網子旁）它會漏掉，而且球**落地靜止後**它就看不到了，偏偏落點決定比分。再加一個用單張圖片訓練的偵測器，補這兩種情況：

```bash
export ROBOFLOW_API_KEY=你的金鑰            # roboflow.com → Settings → API Keys（免費帳號就可以）
uv run --with roboflow python scripts/train_shuttle.py --quick   # 先試跑：3 個 epoch，約 1 小時內
uv run --with roboflow python scripts/train_shuttle.py           # 正式：15 個 epoch，大約一個晚上
```

訓練中隨時按 Ctrl+C 都可以停，會保留到目前為止最好的那一個 epoch，一樣寫出 `models/shuttle_yolo.pt`。`--quick` 只用 25% 的圖片，是用來確認流程能跑，不是拿來用的模型；只想跑 3 輪請用 `--epochs 3`。

腳本會下載 Roboflow Universe 上的公開羽球資料集（約 3–4 GB，CC BY 4.0），合併成單一類別，用 M2 訓練 YOLO11n，完成後寫出 `models/shuttle_yolo.pt`。之後每次分析都會自動使用：

- **補空缺**：TrackNet 兩次看到球之間最多 1 秒的空缺，只在球的軌跡附近搜尋，信心夠高、又落在軌跡上才採用。
- **找落地的球**：每段軌跡結束後 1.5 秒內，在最後位置附近找靜止的球；至少兩個取樣幀都在同一個位置才算。如果那個位置在這一拍之前就已經有球躺著（場邊的備用球），就不採用。

沒有這個檔案時，流程和以前完全一樣；也可以在 `config.toml` 設 `yolo_fill = false` 關掉。

## 準確度

斜角測試片段（3 個回合、10 個人工標記的擊球），全自動、包含自動校正：
- 回合：3 個都找到，但多了 2 個誤判，是撿球、遞球被當成回合。
- 擊球方（近端／遠端）：7/7 正確。
- 比分：
  - 球落地且看得到時，依落點判斷：落在對方場內 → 擊球方得分；出界或掛網落在自己半場 → 對方得分。
  - 球在空中就跟丟時，用整段飛行軌跡做物理擬合（重力 + 空氣阻力），推算落點；離邊線夠遠（超過 1 個標準差）才拿來判分。模擬（0.7 m 低機位、加入校正誤差、球的阻力差異與誤偵測）：判斷落在哪半場 97–100% 正確。
  - 都判斷不了時，猜最後擊球的一方得分（網頁可修正）。
  - 網頁上可以逐回合修正，誤判的回合也可以設成「不算」。

看台很暗、人很多的場館（例如 MCC 螢幕錄影）：羽球常常消失在觀眾背景裡，回合會被切短或漏掉。這是羽球模型（TrackNet）的極限。拍攝時盡量讓背景單純、光線充足。

## 測量值 vs 估算值

| 項目 | 性質 | 說明 |
|---|---|---|
| 回合時間、擊球數 | 測量值 | 漏掉的擊球會少算 |
| 球員位置、球場地圖 | 測量值 | 單鏡頭推算。腳位依相機幾何加權平滑（遠端 1 個像素是好幾公尺深度，所以遠端的深度方向平滑得比較重）；低機位模擬：遠端誤差約 0.3 m（舊版 1.3 m） |
| 球速 | **估算值** | 只有一個鏡頭，球的深度要用推的；誤差約 ±20–30%，超過 450 km/h 的會丟掉 |
| 球種（殺球／高遠／吊球／網前／平抽） | 規則判斷 | 依球速、擊球高度與落點 |
| 體力 | **遊戲化指標** | 回合中每跑 1 m 扣 0.5、衝刺（> 3 m/s）每秒扣 1.5；每一拍依球種扣：殺球 3、防守（接殺）2.5、高遠 2、平抽 1.5、吊球 1.2、網前 1。回合間每秒回 0.6，但只能回到「上限」，上限會隨消耗慢慢下降（疲勞），一場 21 分約剩 30–50。不是生理量測。公式在 `config.toml` 的 `[stamina]` |
| MOVE | 測量值換算 | 最近 3 秒的移動距離 ÷ 8 m |
| 落點評分（PERFECT／GREAT…） | 規則評分 | 依球種的理想落點計算，不是裁判判決 |

## 檔案

```
hud/
  court.py      球場模型、自動偵測（角落可在畫面外）、貼齊白線
  camera.py     從球場單應矩陣還原相機（讓空中的球有 3D 位置）
  detect.py     YOLO11n-pose + 遠端裁切偵測
  players.py    四人身份追蹤（每半場 2 人，匈牙利配對）
  reid.py       跨回合換 ID 修正
  shuttle.py    TrackNetV3 羽球追蹤
  hits.py       擊球、擊球者、球速、球種
  rallies.py    回合切分、落點評分
  score.py      計分（21 分制、deuce、30 分封頂）
  render.py     HUD 影片
  server.py     網頁編輯器（只用 Python 標準函式庫）
  static/index.html
config.toml     可調參數（顏色、回合、計分、體力）
out/<影片>/      每部影片一個資料夾：calib.json、*.parquet、hud.mp4（重跑會覆蓋，不會重複）
```

## 費用與授權

- 全部在這台 Mac 本機執行：沒有付費 API、沒有雲端伺服器、沒有外部資料庫。
- 第三方程式碼與模型：
  - **YOLO11（Ultralytics）**：AGPL-3.0。自己用沒問題；做成公開服務或商業用途，需要開源或另購授權。
  - **TrackNetV3**：MIT（`hud/tracknet/`，只複製了模型定義）。
- 舊版專案移到了 `~/Claude/_archive/badminton-analyzer-old`（沒有刪除）。

## 在其他電腦或雲端繼續開發

```bash
git clone https://github.com/deYewwww/badminton-buddy && cd badminton-buddy
uv sync
for f in tests/test_*.py; do uv run python $f; done
```

- 需要 ffmpeg（Mac：`brew install ffmpeg`；Linux：`apt-get install ffmpeg`）。
- 沒有 Apple 晶片時，會自動改用軟體解碼和 CPU，速度較慢。
- 影片和分析結果不在 git 裡。

## 測試

```bash
for f in tests/test_*.py; do uv run python $f; done
```

其中包含一個合成畫面測試：兩個角在畫面外時，自動偵測仍要把球場放對（誤差 < 15 cm）。
